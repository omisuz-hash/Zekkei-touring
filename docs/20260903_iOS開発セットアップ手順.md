# iOS 開発セットアップ手順（絶景道アプリ）

作成日: 2026-09-03

本リポジトリの `ios/` 配下は SwiftUI アプリの土台コードである。Linux 環境で作成したため、Mac 上でのビルド確認は未実施。以下の手順で Xcode プロジェクトを生成し、動作確認を行う。

## 1. 必要なもの

- Mac（macOS 14 以降）と Xcode 16 以降
- Apple Developer Program（TestFlight 配布・実機の位置情報バックグラウンド確認に必要）
- Supabase プロジェクト（無料枠で可）
- Google Cloud の OAuth クライアント ID（iOS 用）

## 2. プロジェクト生成とコンパイル（1 コマンド）

```bash
cd ios
./20260905_setup_xcode.sh
```

スクリプトが、Xcode と Homebrew の有無を確認 → xcodegen を導入 → `~/.zekkei_supabase` から接続先を `Local.xcconfig`（git 管理外）に書き出し → `project.yml` から Xcode プロジェクトを生成 → シミュレータ向けにコンパイルしてエラーを表示 → Xcode で開く、まで行う。依存パッケージ（supabase-swift、GoogleSignIn-iOS）は自動取得される。

- 無料の Apple ID で「Sign in with Apple」の署名エラーが出るときは `./20260905_setup_xcode.sh --no-apple-signin`
- Google ログインを使うには、環境変数 `GOOGLE_IOS_CLIENT_ID`（Google Cloud の iOS 用 OAuth クライアント ID）を `~/.zekkei_supabase` に足してから再実行する。未設定でも Apple ログインとモックは動く

## 3. 接続先について

接続先は `Local.xcconfig` 経由で Info.plist に入る（`SupabaseURL` / `SupabaseAnonKey` / `GoogleClientID`）。値が未設定の間は、アプリはテスト用データ（モック）で動作する。`project.yml` を手で編集する必要はない。

## 3.5 Supabase アカウント・プロジェクト作成時の注意

- **リージョン**: 「Northeast Asia (Tokyo)」を選ぶ。日本の利用者の応答が速く、後から変更できない
- **プロジェクト名**: `zekkei-touring`。データベースのパスワードは自動生成のまま、パスワード管理ツールに保存する（後で再表示できない）
- **プラン**: 開発中は Free。Free は 1 週間操作が無いと一時停止するので、公開前に Pro（月 $25）へ上げる。組織（Organization）は個人名で良い
- **拡張機能**: PostGIS は SQL の先頭（`create extension postgis`）で有効化されるため、画面操作は不要
- **控える値（3 つ）**: Project Settings → API の「Project URL」「anon public key」「service_role key」。service_role は管理用で、アプリには入れない（サーバー側と自動収集の流し込みだけで使う）
- **認証（Authentication → Providers）**: Google を有効化し、Google Cloud の「iOS 用 OAuth クライアント ID」を登録する。Apple を有効化するには Apple Developer Program の登録が必要なので、TestFlight 直前で良い
- **Storage**: バケットは SQL で作られるので手動作成は不要
- **Security**: 「Enable email confirmations」は既定のままで良い（Google/Apple ログインのみ使うため影響しない）
- **自動収集の流し込み**: `tools/seedpipeline/out/<日付>_seed_roads_auto.sql` は数 MB あるため、SQL Editor の貼り付けではなく Supabase CLI（`psql` 相当）で流す。手順は流し込み時に別途案内する
- **費用アラート**: Organization → Billing → Spend cap を「有効」にしておくと、想定外の課金が止まる

## 4. データベースの初期化（Mac から、追加インストール不要）

接続情報を対話で登録してから、`tools/supabase/20260905_db_admin.py` で SQL を適用する。Personal Access Token は https://supabase.com/dashboard/account/tokens で作成する（名前は `zekkei-admin` 等）。

```bash
cd tools/supabase
./20260905_setup_supabase.sh          # URL・Publishable key・Secret key・Personal Access Token を登録し検証
./20260905_setup_supabase.sh --token-only   # Personal Access Token だけ入れ直す（失効時。他の項目は変更しない）

配布（TestFlight）について: 初回だけ `./20260905_setup_xcode.sh --team 7K9RFXW9AV` で Team ID を登録する（`~/.zekkei_ios` に保存。git 管理外）。以後は `./20260905_setup_xcode.sh --archive` で配布用の .ipa を書き出せる。ビルド番号は実行日時から自動で付くため、同じ番号で弾かれることはない。表示用の版を変えるときは `ZEKKEI_VERSION=0.2.0 ./20260905_setup_xcode.sh --archive`。

シミュレータについて: 使う端末は初回に決めて `~/.zekkei_sim` に保存し、以後は固定する。端末が毎回変わるとホーム画面からアイコンが消えるため。別の端末に変えたい場合は `rm ~/.zekkei_sim` してから `--run` を実行する。ビルドせずにアプリだけ開き直すには `~/zekkei-open`（`--run` 実行時に自動で作られる）。
source ~/.zekkei_supabase
python3 20260905_db_admin.py migrate  # supabase/migrations/*.sql を日付順に適用（適用済みは飛ばす）
python3 20260905_db_admin.py seed     # 手作業シード 22 本と、自動収集シード（最新）を流し込む。何度流しても二重登録されない
python3 20260905_db_admin.py stats    # 件数の確認
```

Supabase の Authentication > Providers で Google と Apple を有効にし、Google のクライアント ID を登録する。

月次無料枠の付与は `grant_monthly_free_credits()` を毎月 1 日に実行する。Supabase の pg_cron 拡張で以下を登録する。

```sql
select cron.schedule('grant-monthly-credits', '5 0 1 * *', $$select public.grant_monthly_free_credits()$$);
```

## 5. 動作確認の順序

1. シミュレータで起動し、「探す」タブにサンプルの絶景道が表示されることを確認する。
2. 実機で「記録」タブから記録を開始し、位置情報の「常に許可」ダイアログを確認する。
3. 走行後に記録を終了し、区間の切り出し画面でスライダーが動くことを確認する。
4. ログイン後に投稿し、Supabase の `zekkei_roads` と `road_ratings` に行が入ること、閲覧枠が 3 件増えることを確認する。

## 8. 外部テスト（TestFlight ベータ）に進むための確認項目

内部テスト（自分の端末）と違い、**外部テストには Apple のベータ版審査がある**。審査は公開審査より軽いが、落ちる箇所はほぼ決まっている。以下を順に埋める。

### 8.1 アプリ側で済んでいるもの

| 項目 | 根拠となる審査条項 | 状態 |
|---|---|---|
| Apple でサインイン | 5.2 / 4.8（他社ログインを出すなら必須） | 実装済み |
| アカウント削除（アプリ内） | 5.1.1 (v) | マイページに実装済み |
| 通報・ブロック | 1.2（投稿型アプリの必須要件） | 実装済み |
| 利用規約・プライバシーポリシーへの同意 | 1.2 / 5.1.1 | ログイン画面に表記あり |
| 位置情報の用途説明 | 5.1.5 | Info.plist に記載済み |
| 輸出コンプライアンス | — | `ITSAppUsesNonExemptEncryption: false` |
| プライバシー manifest | 2024 年以降の必須要件 | `Resources/PrivacyInfo.xcprivacy` |

### 8.2 App Store Connect 側で埋めるもの

1. **「App のプライバシー」の質問票**。取得する情報の申告。`web/zekkeido/privacy.html` と `PrivacyInfo.xcprivacy` の内容に合わせる（位置情報・写真・投稿内容・メールアドレス・識別子、いずれも追跡なし）
2. **ベータ版 App 情報**。説明文、フィードバック送信先（`support@tidalworks.jp`）、連絡先
3. **サポート URL** `https://tidalworks.jp/zekkeido/`、**プライバシーポリシー URL** `https://tidalworks.jp/zekkeido/privacy/`
4. **審査用メモ**。位置情報を「常に許可」で使う理由と、テスト手順（記録 → 切り出し → 評価投稿 → 閲覧枠の消費）を日本語で書く。ここを厚くすると差し戻しが減る

### 8.3 判断が要るもの

- **Google ログイン**: iOS では Apple でサインインがあれば足りる。開通させないなら、ログイン画面からボタンごと外す。**動かないボタンを残したまま審査に出すのは避ける**
- **月額プラン**: ベータの目的は「投稿が集まるか」「閲覧枠 10 / 月が妥当か」の確認であり、課金はその後で足りる。TestFlight の課金は sandbox なので、支払い意思の確認にもならない。ボタンは「準備中」のまま残すか、非表示にする
