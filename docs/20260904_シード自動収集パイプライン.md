# シード自動収集パイプライン（設計・運用手順）

作成日: 2026-09-04
目的: 人が介在せずに、YouTube のツーリング動画から「絶景道」の初期データベースを蓄積する
場所: `tools/seedpipeline/`

---

## 1. 全体像

```
① 発見     YouTube Data API  検索キーワード（「絶景 ツーリング」等 29 語）と、当たりの多いチャンネルの投稿一覧
② 取得     YouTube Data API  概要欄・チャプター・タグ・コメント（関連度順 60 件）
③ 抽出     Gemini API        テキストから「走った道の区間」を JSON で抽出。概要欄が薄い動画は Gemini に動画そのものを見せる
④ 形状     地図 API          始点・経由地・終点を座標にし、道路に沿った形状を取る（Google Geocoding + Routes、または OpenStreetMap）
⑤ 統合     ローカル          名前の正規化と形状の重なりで同じ道を 1 本にまとめ、言及数を数える
⑥ 出力     ローカル          Supabase 用 SQL、GeoJSON（地図で目視確認用）、レポート
```

すべての進捗は SQLite（`out/seedpipeline.sqlite`）に保存される。途中で止まっても、次回は続きから再開する。毎日 1 回実行すれば、YouTube の無料枠の範囲で自動的に溜まっていく。

## 2. 必要な API と費用

| API | 役割 | 取得先 | 費用の目安 |
|---|---|---|---|
| YouTube Data API v3 | 動画の発見と概要欄・コメントの取得 | Google Cloud Console（取得済み） | 無料。1 日 10,000 ユニット。検索 1 回 100、動画詳細・コメントは 1 |
| Gemini API | 道の抽出（テキスト）、映像解析（補助） | Google AI Studio https://aistudio.google.com/ | 無料枠あり。有料化すると 1 動画のテキスト抽出 1 円未満、映像解析 30 分で数十円程度 |
| Google Maps Platform（Geocoding API、Routes API） | 地名→座標、道路の形状 | Google Cloud Console。**課金登録（カード）が必要** | 月あたり各 API に無料枠あり（数千〜1 万リクエスト）。道 1 本で 3〜6 リクエスト。1,000 本でも無料枠内の見込み |

Google Maps のキーが無い場合は、OpenStreetMap（Nominatim + OSRM）で代替する。無料でキー不要だが、1 秒 1 リクエストの制約と精度の低下があり、大量処理と商用利用には向かない。**本番のシード作成は Google 推奨。**

### 2.1 Google Maps Platform の設定手順

1. Google Cloud Console で YouTube と同じプロジェクトを開く
2. 「お支払い」で請求先アカウントを作成（カード登録）
3. 「API とサービス」→「ライブラリ」で **Geocoding API** と **Routes API** を有効化
4. 「認証情報」→「API キーを作成」。「API の制限」で上記 2 つに限定
5. 予算アラートを設定（例: 月 3,000 円）

### 2.2 Gemini API の設定手順

1. https://aistudio.google.com/ で Google アカウントにログイン
2. 「Get API key」→「Create API key」で、YouTube と同じ Cloud プロジェクトを選ぶ
3. 無料枠で試し、1 日あたりの上限に当たるようなら「有料プラン」に切り替える（同じキーのまま）

## 3. 初回の実行手順（Mac）

```bash
cd <このリポジトリ>/tools/seedpipeline
python3 20260904_seed_pipeline.py selftest            # API を使わない動作確認

# キーを 1 か所にまとめる（チャットやリポジトリには書かない）
cat > ~/.zekkei_keys <<'EOS'
export YOUTUBE_API_KEY=ここにキー
export GEMINI_API_KEY=ここにキー
export GOOGLE_MAPS_API_KEY=ここにキー
EOS
chmod 600 ~/.zekkei_keys
source ~/.zekkei_keys

# まず取得済みの 17 本で流れを確認（YouTube の枠を使わない）
python3 20260904_seed_pipeline.py import-json ../youtube/out/20260904_youtube_videos.json
python3 20260904_seed_pipeline.py extract
python3 20260904_seed_pipeline.py georeference
python3 20260904_seed_pipeline.py dedupe
python3 20260904_seed_pipeline.py export
```

`out/<日付>_roads_auto.geojson` を https://geojson.io に貼ると、抽出された道が地図に描かれる。ここで形状の妥当性を目視できる。

## 4. 自動運転

```bash
./20260904_run_daily.sh        # 1 日分（YouTube 9,000 ユニット）を実行して out/ に書き出す
```

毎日自動で回すには、Mac の launchd に登録する。ターミナルで次を実行する（パスは各自の場所に置き換える）。

```bash
cat > ~/Library/LaunchAgents/com.zekkei.seedpipeline.plist <<'EOS'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.zekkei.seedpipeline</string>
  <key>ProgramArguments</key><array><string>/bin/bash</string><string>/Users/omi_mba/path/to/Zekkei-touring/tools/seedpipeline/20260904_run_daily.sh</string></array>
  <key>StartCalendarInterval</key><dict><key>Hour</key><integer>3</integer><key>Minute</key><integer>0</integer></dict>
  <key>StandardOutPath</key><string>/tmp/zekkei_seed.log</string>
  <key>StandardErrorPath</key><string>/tmp/zekkei_seed.err</string>
</dict></plist>
EOS
launchctl load ~/Library/LaunchAgents/com.zekkei.seedpipeline.plist
```

Mac がスリープしていると実行されないため、常時起動の Mac か、クラウドの小さなサーバー（月数百円）に置くのが確実。

### 4.1 1 日あたりの処理量の目安

| 段階 | 上限 | 根拠 |
|---|---|---|
| 検索 | 29 語 × 2 ページ = 58 回（5,800 ユニット）。2 日目以降は未実施分と当たりチャンネルの投稿一覧のみ | 検索は 100 ユニットと高い |
| 取得 | 300 本/回（約 600 ユニット） | 動画詳細 1 + コメント 1 |
| 抽出 | 300 本/回、映像解析は 20 本/回まで | Gemini の枠 |
| 形状 | 200 本/回 | 地図 API の無料枠 |

初日で検索 58 回 → 約 2,500 本の候補が見つかり、その後は毎日 300 本ずつ処理される。**2〜3 週間で 3,000 本以上の動画から 500〜1,000 本規模の道**が集まる見込み（ツーリング動画の 4〜5 割から道が取れ、重複統合で 3〜4 割に圧縮される想定）。

## 5. 品質管理（人が介在しない前提での安全弁）

- **抽出の確度**: Gemini に道ごとの確度（0〜1）と根拠の引用を出させ、出力時は確度 0.5 以上に絞る（`export --min-confidence`）
- **形状の妥当性**: 始点・終点が日本国内、直線距離 300m〜250km、経路長 500m〜300km、経路が直線距離の 4 倍を超えない、を機械判定。外れた道は「形状 NG」として保留
- **重複統合**: 通称の正規化（表記ゆれ・路線番号）と、形状の 80% 以上の重なりで統合。言及数の多い方を残す
- **対象外の除外**: タイトルとタグの語で用品レビュー・納車・事故動画を除外し、さらに Gemini が「ツーリング走行動画でない」と判定したものを除外
- **再実行の安全性**: 出力 SQL は `seed_key` で同一判定し、再実行しても二重登録されない

自動収集の結果はレポート（`out/<日付>_seed_report.md`）で一覧できる。公開前に一度だけ、言及数上位から目視で確認することを推奨する（必須ではない）。

```
  20260904_run_daily.sh       毎日実行用
  seedpipeline/

    store.py      SQLite（進捗・結果・利用枠）
    export.py     SQL / GeoJSON / レポート
    pipeline.py   各段階の実行
  out/            SQLite、出力ファイル、ログ（git 管理外）
supabase/migrations/20260904_road_videos.sql   道と動画の多対多、source / geometry_quality / seed_key 列
```

## 8. 既知の制約・今後

- Gemini の映像解析は YouTube の公開動画のみ対象。限定公開・年齢制限付きは不可
- OSRM のデモサーバーは商用利用不可のため、本番は Google Maps を使う
- 検索キーワードは `config.py` で追加できる。地域名 × 「絶景 ツーリング」の組み合わせを増やすと網羅性が上がる
- 抽出した「示唆値」（絶景度・ワインディング度など 1〜5）は動画からの推定であり、ユーザー評価とは分けて扱う（ユーザー評価が付いたら置き換わる設計）
