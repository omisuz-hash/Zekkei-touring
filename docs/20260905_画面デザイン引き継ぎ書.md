# 絶景道（Zekkei-do）画面デザイン 引き継ぎ書（Claude Design 向け）

作成日: 2026-09-05
用途: Claude Design に渡し、主要画面のモックアップと UI の基本要素（配色・文字・部品）を作ってもらうための仕様
成果物の希望: iPhone 実寸のアートボードで主要 5 画面＋補助画面、共通部品一覧、配色と文字の定義。PNG/PDF で書き出せる形

---

## 1. プロダクト概要

- 名称: 絶景道（ぜっけいどう / Zekkei-do）。iPhone アプリ
- 一言で: 「この道は走ると景色が良くて気持ちいい」をライダー同士で共有する、道の口コミ地図
- 中核概念: **絶景道** = ライダーが「ここからここまで」と区切った、走って気持ちの良い道の区間（線）。観光地（点）ではなく道（線）を扱う
- 既存アプリとの違い: ナビではない。ナビは Google マップ等に任せる。評価の対象は「ルート全体」ではなく「区間」
- 初期データ: YouTube のツーリング動画から自動抽出した約 400〜1,000 本の道（ビーナスライン、志賀草津、やまなみハイウェイ、エサヌカ線 など）。各道に紹介動画のリンクが付く

## 2. 利用者と利用場面

- 主な利用者: 30〜60 代の日本のバイク乗り。ツーリングを計画する人、走った道を記録して人に教えたい人
- 場面 A（計画・自宅）: ソファで地図を眺め、次に走る道を探す。動画で雰囲気を確かめる
- 場面 B（走行前後・屋外）: 発車時に記録を開始し、降車時に停止する。グローブ着用、日差しの下、片手操作
- 場面 C（帰宅後）: 走行記録から公開する区間を切り出し、評価と写真を付けて投稿する
- 利用者は技術に詳しくない前提。説明は短く、専門用語を使わない

## 3. デザインの方向性

- 印象: 開放感、朝の高原の空気、静かな高揚感。派手さより「信頼できる地図」
- 主役は地図と写真。UI は地図を邪魔しない薄い皮膜（ガラス感のある半透明パネル）
- アクセント色: 暖色のオレンジ（現状コードでは `Color.orange` 相当）。絶景度の高い道ほど赤〜オレンジで濃く、評価が少ない道は灰色
- 文字: iOS 標準（SF / ヒラギノ）。数値は等幅で揃える
- ダークモード対応必須（夜間走行前後の利用が多い）
- 操作性: タップ領域は最低 44pt、走行前後の画面（記録）は主要ボタンを 60pt 以上の大きさに。グローブでも押せる
- 屋外の視認性: 記録画面はコントラスト高め、細い文字を使わない
- トーン（文言）: 丁寧だが短い。「〜してください」より「〜する」。断定的・脅迫的な表現は避ける（例: 「確定」ではなく「確認」）

## 4. 情報構造（タブ）

下部タブ 4 つ。

1. 探す（地図）
2. 記録
3. 走行記録（一覧 → 切り出し → 評価投稿）
4. マイページ

## 5. 主要画面の仕様

### 5.1 探す（地図）

- 目的: 周辺や行き先の絶景道を見つける
- 要素: 全画面の地図。絶景道は線で描画（色 = 絶景度、太さ = 閲覧済みなら太く）。線の始点にマーカー（動画由来の道は再生アイコン、ユーザー投稿はスター）
- 上部: 検索窓（地名・道名）、右上に「閲覧枠の残り」バッジ（例: 🎫 3 / サブスク会員は ∞）
- 左下: 凡例（赤 = 絶景度 4.5 以上、橙 = 3.5 以上、灰 = 評価が少ない）
- 右下: 現在地ボタン、コンパス
- タップ: 線またはマーカーをタップすると下からシートが上がる（5.2）
- フィルタ（第 2 段階で可）: 絶景度、距離、ワインディング度、動画あり、未閲覧のみ
- 空状態: 周辺に道が無いときは「この付近にはまだ絶景道がありません。走って最初の 1 本を投稿しませんか」
- 読み込み中: 上部中央に小さなインジケータ

### 5.2 道の詳細（シート → 全画面）

- 半分の高さのシートで概要、引き上げると全画面
- 概要（閲覧枠を使う前に見える部分）
  - 道の名前、都道府県、区間（始点 〜 終点）、距離、曲がり具合（%）
  - 総合スコア（大きく 1 つ、例 4.6）と評価件数
  - 小さな地図に線
  - 動画由来なら「動画・編集部から登録された道」の表示
- 解放操作（未解放時）
  - ボタン「閲覧枠を 1 つ使って見る（残り 3）」。残りが 0 なら無効化し、「絶景道を投稿すると閲覧枠が増えます。月額プランなら無制限です」の案内と「月額プランを見る」
  - 未ログインなら「ログインして見る」
- 解放後に見える部分
  - 5 軸の評価バー: 絶景度 / 走りやすさ（路面・道幅）/ ワインディング度 / 休憩所 / 絶景スポットの駐車。各 5 点満点の横バー＋数値
  - 紹介文（自動抽出の要約。注意事項があれば「注意: 冬季閉鎖」など目立つ小さなラベル）
  - 写真・動画の横スクロール（正方形サムネイル、動画は再生アイコン）。タップで全画面
  - この道が登場する YouTube 動画の一覧（サムネイル、タイトル、チャンネル名、登場時刻）。複数本。タップで YouTube へ
  - ライダーのコメント一覧（各 5 軸の点、季節、コメント文）
  - ボタン「Google マップでこの区間へナビ」
  - 右上メニュー: 通報。コメントの長押しで「通報」「この投稿者をブロック」
- 設計の意図: 「見るのに枠を使う」ことの納得感を高めるため、解放前でもスコアと形状は見せる

### 5.3 記録

- 目的: 発車〜降車を記録する。屋外・グローブ・片手
- 要素: 地図（現在地追従、走行軌跡を青線）。下部に大きなパネル
  - 数値 3 つ: 距離、時間、状態（停止中 / 記録中 / 一時停止）
  - 巨大ボタン 1 つ: 「記録を開始」（橙）→ 記録中は「記録を終了」（赤）
  - 注意文（小さく）: 「記録は端末内に保存され、あなたが切り出した区間だけが公開されます」
  - 権限の案内: 位置情報が「使用中のみ」のとき「画面を閉じても記録を続けるには『常に許可』が必要です」
- 終了時: 自動で「区間の切り出し」画面（5.4）へ遷移
- 状態: 停車が 5 分続くと「一時停止」表示（自動）。GPS 未取得時のプレースホルダ

### 5.4 区間の切り出し

- 目的: 走行記録から公開する区間だけを選ぶ（自宅を晒さない）
- 要素: 地図に走行軌跡（灰）と選択区間（橙、太）。始点に緑の旗、終点にチェッカー旗
- 下部パネル: 「公開する区間を選ぶ」見出し、説明文「自宅周辺（プライバシーゾーン）は自動で除外されています」
  - スライダー 2 本（始点 / 終点）。それぞれ右に距離表示（例 12.4 km）
  - 選択区間の情報: 距離、曲がり具合（%）
  - ボタン「この区間を絶景道として評価する」。500 m 未満は無効化し赤字で注意
- 設計の意図: 地図上のハンドルの直接ドラッグより、スライダーの方が誤操作が少ない。両方あっても良い

### 5.5 評価投稿

- 目的: 区間に名前と評価を付けて投稿する
- 要素（フォーム）
  - 道の名前（必須）、始点の目印、終点の目印、都道府県
  - 5 軸の星（各 1〜5、既定 3）: 絶景度（景色の良さ・開放感）、走りやすさ（路面の良さ・道幅）、ワインディング度（カーブの多さ・楽しさ）、休憩所（道の駅・売店・トイレ）、絶景スポットの駐車（景色の良い場所でバイクを停められるか）
  - おすすめの季節・時間帯（選択）、交通量（任意）
  - コメント、道の紹介（新規登録時のみ）
  - 写真・動画: 横並びサムネイル＋「写真・動画を追加」。写真 5 枚まで、動画 1 本（30 秒・720p に自動圧縮）。長い動画は YouTube の URL 欄へ
  - 紹介動画の URL（任意）
  - ボタン「投稿する」。注記「投稿 1 件につき閲覧枠が 3 つ増えます。区間の形状と評価のみ公開されます」
- 重なり確認ダイアログ: 「同じ道が登録済みです（区間の 85% が重なっています）」→「既存の『ビーナスライン』に評価を追加」「別の道として新規登録」「キャンセル」
- 完了: 「投稿しました。閲覧枠の残り: 6」

### 5.6 補助画面

- ログイン: アプリ名とアイコン、説明「収集するのは名前とメールアドレスのみです」、「Apple でサインイン」（黒）、「Google でログイン」
- 走行記録一覧: 日時、距離、点数、投稿件数。スワイプで削除
- マイページ: アカウント（名前、コース）、閲覧枠（残り、仕組みの説明、「月額プランを見る」）、プライバシーゾーン（中心の設定、半径スライダー 300〜3,000 m、「現在地を中心に設定」）、サポート（問い合わせ、利用規約・プライバシーポリシー、通報の説明）
- 有料プラン案内（第 2 段階）: 「投稿コース」と「月額プラン」の比較。月額 380 円案、年額はその 10 か月分

## 6. 共通部品

- 絶景道の線（色 3 段階＋閲覧済みの太線）
- スコアの大きな数字＋件数
- 5 軸バー（ラベル・アイコン・バー・数値）
- 星入力（5 つ、44pt 以上）
- 閲覧枠バッジ
- 半透明パネル（地図の上に載るカード）
- 写真・動画サムネイル（正方形、動画は再生アイコンと秒数）
- 注意ラベル（冬季閉鎖、夜間通行止め、二輪通行禁止、観光渋滞）
- 空状態・読み込み・エラーの表現

## 7. 実装上の制約（デザインが守ると実装が速い）

- iOS 17 以降、SwiftUI と Apple 標準の地図（MapKit）。独自の地図タイルは使わない
- 標準部品（シート、リスト、フォーム、タブ）を活かす。独自部品は上記 6 の範囲に留める
- Apple 審査要件: 通報・ブロックの導線、連絡先の表示、ログインの選択肢に Apple を含める、位置情報の目的説明
- 動画の埋め込み再生はしない（YouTube へのリンク）。閲覧枠の内側に動画を置かない（無料側に置く）

## 9. 現状のコードとの対応（参考）

画面ごとの実装ファイル（`ios/ZekkeiTouring/Views/`）: ExploreMapView（探す）、RoadDetailView（道の詳細）、RecordView（記録・走行記録一覧）、TrimView（区間の切り出し）、RateView（評価投稿）、MediaPickerSection（写真・動画）、SignInView、ProfileView。デザインの成果物は、この構成に沿って画面単位で出してもらえると実装に反映しやすい。
